# Chytach для Windows

Читалка на тому самому Readium, що й версії для macOS, iOS та Android, але
іншим шляхом: тут немає ні Swift-, ні Kotlin-тулкіта. Текст малює
[TypeScript-тулкіт](https://github.com/readium/ts-toolkit) усередині
вебвʼю, а Tauri дає вікно й доступ до диска.

## Будова

- `src/epub/manifest.ts` — розбирає EPUB у маніфест Readium. Цієї частини в
  TypeScript-тулкіті немає: `@readium/shared` уміє лише `HttpFetcher` і
  чекає готовий маніфест із сервера. У Swift і Kotlin ту саму роботу робить
  Streamer.
- `src/epub/ZipFetcher.ts` — віддає розділи прямо з розпакованого архіву.
- `src/appearance.ts` — оформлення сторінки; значення ті самі, що в інших
  версіях, бо вони вже виміряні на пікселях.
- `src-tauri/src/lib.rs` — тримає розпакований архів і віддає з нього файли
  схемою `epub`. Без цього не вантажились би картинки та стилі всередині
  розділу: Readium ставить документу `<base>` на справжню адресу.

## Чому шлях до книги не ходить через вебвʼю

Розділи книги малюються в iframe, якому Readium дає і скрипти, і спільне
походження. Отже код із книги дотягується до мосту Tauri. Якби команда
приймала шлях від вебвʼю, книга попросила б прочитати будь-який файл і
забрала б його назад через схему `epub`.

Тому шлях приходить лише звідти, де його обрала людина: з рідного діалогу
(`pick_book`), з аргументів запуску (`open_startup_book`) або з власної
памʼяті застосунку (`open_last_book`). Жодна команда не бере шлях
параметром.

## Чому CSP сторінки вимкнена

Кадр із розділом створюється з `blob:` і успадковує політику сторінки, а
WebKit і Chromium застосовують її по-різному. Під WKWebView будь-яка
політика, що на вигляд дозволяла все потрібне, зупиняла навігатор на
`load()`. Вмикати її можна тільки разом із перевіркою на справжньому
Windows, інакше це політика, випробувана на одному рушії з двох.

Що обмежує книгу вже зараз: Readium дає кожному кадру власну CSP із
`connect-src 'none'`, тож віднести здобуте в мережу з кадру нікуди, а
команди Rust не приймають шляхів.

## Збірка

```bash
pnpm install
pnpm dev              # у браузері, зі зразком книги
pnpm exec tauri dev   # у вікні застосунку
```

Файл для Windows (`.msi` і `.exe`) збирається тільки на Windows — з macOS
його не злінкувати. Це робить `.github/workflows/windows.yml`: вручну на
сторінці Actions або автоматично на теґ `win-v*`.
